# 方寸九宫整体优化企划案

- 日期：2026-10-11
- 状态：v1.8（2026-10-12）；首批体验、五章九十关、七道新版每日题、滑动选关及庭院成长表现已完成开发。六道重力体验题＋自由局已接入最新开发版的庭院布局页，保留独立预览。霜封石、来访册等仍为后续企划；本轮未加固或上传。
- 范围：目标表达、两种主模式、重力试验玩法、关卡机制、社交求助、成长奖励、广告、交互视觉、开源参考与验证计划。
- 核心建议：先让玩家知道“现在做什么、这一局为什么玩、下次为什么回来”，再扩展机制。保留庭院与闯关两种主入口，默认使用完整 9×9 棋盘，6×9 为可选变体；撤回采用有限免费次数，不增加基础游玩的体力门槛。

## 1. 当前最优先的问题：玩家不清楚目标

用户反馈“目标不清楚”比“内容不够多”更值得优先处理。它可能包含三个不同问题：

| 玩家疑问 | 应给出的答案 | 主要位置 |
| --- | --- | --- |
| 我现在该怎么操作？ | 拖动下方方块，填满一行、一列或一个 3×3 九宫即可消除 | 首次操作、棋盘旁的简短教学 |
| 我这一局要完成什么？ | 庭院尽量腾出空间、挑战得分；闯关在限定步数内完成明确目标 | 模式入口、对局目标卡 |
| 我为什么要继续玩？ | 消除与通关推进装饰收集，逐步装点自己的庭院 | 首页、结算、收藏预览 |

**“落子成局，方寸之间”可以保留为气质文案，但不能承担玩法说明。** 同样，“自由摆放”“小径打通了”不能单独解释胜负和奖励。

目标不清楚的具体成因尚未经过用户观察验证。下面是待验证的设计假设，不把它直接等同于留存低的全部原因。

### 1.1 建议的统一介绍

> 拖动方块完成消除，解开关卡，慢慢装点自己的庭院。

这句话是游戏整体方向；进入模式后必须继续说明本局目标。

| 入口 | 建议说明 | 主按钮 |
| --- | --- | --- |
| 清雅庭院 | 填满行、列或九宫，腾出空间挑战高分；消除还能解锁庭院装饰 | 开始摆放 / 继续这一局 |
| 闯关挑战 | 在限定步数内完成本关目标，通关后可以重玩争取三星 | 继续第 X 关 |
| 每日精选 | 每天一道固定题目，完成后留下今日印记，可反复挑战更少步数 | 挑战今日题目 |
| 落玉庭（体验） | 消除后玉块会下落，试着触发连锁 | 体验重力玩法 |

### 1.2 每种模式只突出一个主目标

- 庭院：得分与空间管理是本局主目标；装饰进度是长期回报。明确“不限时，没有固定通关分数；当前托盘全部放不下时本局结束”。
- 闯关：目标图标、剩余数量与剩余步数必须同时可见。首次通关时，三星要求作为次要信息。
- 每日精选：完成当天题目是主目标；步数比较在通关后出现。
- 新机制体验题：先完成一次对应效果，再给组合任务，不同时教三种规则。

### 1.3 开局、局中、结算必须前后一致

闯关示例：

| 时点 | 展示内容 |
| --- | --- |
| 开局 | “8 步内，让 1 处花圃开花”＋与棋盘相同的花圃图标 |
| 局中 | “花圃还差 1 次浇灌 / 剩余 3 步”；拖动时预览是否会浇灌 |
| 通关 | “花圃已开花，目标完成”；再显示星级与重玩入口 |
| 失败 | “步数用完，花圃还差 1 次浇灌”；提供返回棋盘调整、重试、求助 |

庭院示例：

| 时点 | 展示内容 |
| --- | --- |
| 开局 | “填满行、列或九宫消除，尽量留下更多空位” |
| 局中 | 主信息显示分数；次信息显示当前选定装饰还差多少次消除 |
| 结束 | 说明“托盘方块都放不下了”；显示本局得分和实际推进的装饰进度 |
| 下一局 | 保留玩家选定的收藏目标，不要求再次选择 |

关键规则说明不应被普通“漂亮”“连消”等反馈长时间覆盖。短暂反馈结束后，目标卡恢复原位。

### 1.4 首次体验节奏

1. 首屏能看见玩法说明与当前庭院目标，不增加长篇开场剧情。
2. 第一次拖动：只教合法落子。
3. 第一次消除：明确“填满就消除”，再展示修竹实际获得。
4. 幸运方块出现时：解释它的来源与作用。
5. 第一局结束：展示本局推进了什么，再提供开始下一局。

这些步骤部分已有实现，重点是统一表达和反馈顺序，不重复制作另一套教程。

## 2. 当前基础与改版边界

依据本次及前次查看的开发源码，已有：两种主模式、五章九十关、三种庭院布局（方庭、石台、星位）、每日精选、收藏目标、存档、撤回、机制教学、消除预览、同关分享与步数比较、分析上报入口。

以上是企划基础。2026-10-11 首批实现后已执行自动回归与小屏画面检查，记录见 `../updates-2026-10-11/首批更新与维护说明.txt`；尚未执行微信真机及真实广告验收，不能据此替代发布验收。

| 已有基础 | 下一步重点 |
| --- | --- |
| 新手引导与机制说明 | 玩家是否能复述目标；开局、棋盘、结算是否使用同一套词 |
| 收藏与自选目标 | 把隐藏在收藏里的进度带到首页和结算 |
| 关卡重玩与星级 | 先肯定完成目标，再邀请挑战更少步数 |
| 同关分享 | 增加失败时的求解语境，后续再支持实际残局 |
| 每日精选 | 增加有节奏的主题组织，避免再建一套重复入口 |
| 自定义事件上报入口 | 确认后台实际配置与收到的数据，不能把代码存在视为分析已生效 |

不建议在这一轮重写引擎、把全部关卡改成物理玩法，或加入金币、钻石、木材等多套货币。

## 3. 产品结构与长期目标

首页保持“清雅庭院 / 闯关挑战”两个主入口。每日精选作为次入口；重力玩法先以小型特别玩法出现。收藏与来访册统一放在“我的庭院”内。

玩家成长路径：

**完成一次消除 → 看见庭院变化 → 选择下一件装饰 → 自由摆放或挑战关卡 → 解锁装饰并陈列 → 明天体验新的精选题目。**

庭院建设不应成为强制任务：喜欢单纯刷分的玩家可以忽略收藏，喜欢解谜的玩家不必先刷无尽模式。

## 4. 清雅庭院：给自由玩法一个清楚的方向

### 4.1 保留轻松基础

- 完整 9×9 方庭是默认棋盘及新手推荐，不增加随机冰块或突然变化的物理规则。
- 按最新确认，长庭、曲院从庭院选择与好友榜移除；旧记录保留。默认仍是完整 9×9 方庭。
- 其他地图在选择卡上说明禁区、缺角、长宽差异。
- 不限时间、免费游玩，保持可随时离开并继续。
- 排行榜继续按地图区分；装饰和皮肤不改变分数与发牌概率。

### 4.2 先展示现有成长，再测试“本局小愿望”

第一阶段先把现有收藏进度常驻到合适位置，例如“梅花还差 6 次消除”。结算同时展示“本局完成 3 次消除，梅花还差 3 次”，所有数字来自实际存档。

第二阶段再小范围试验每局一个可选小目标：完成三次九宫消除、完成一次双重消除等。目标不改变胜负、不增加排行榜分数，也不要求玩家放弃已有策略。

首版小愿望只给纪念记录或结算表扬，不直接改写现有装饰的消除次数要求。若后续增加外观奖励，另行定义领取和撤回规则，避免把一次操作反复撤回用于刷奖励。

### 4.3 有意义的结束反馈

每局只突出一项表现：刷新纪录、一次多重消除、收藏解锁或目标推进。明确得分与装饰进度的区别，不用一排难以理解的统计取代反馈。

## 5. 闯关挑战：目标清楚，难度来自选择

### 5.1 保持固定发牌

主线继续固定布局与发牌。相同关卡、相同规则版本、相同操作应产生相同结果，便于教学、验证三星路线、撤回与好友讨论。

不通过随机坏牌增加难度。难度从“先消哪里、先腾哪片空间、先开哪扇门”产生。

### 5.2 章节节奏

建议以后每章按“学习 → 运用 → 组合 → 精通”编排，十二关可暂按 2 / 4 / 4 / 2 的比例制作，再通过真人试玩调整。这是设计起点，不是当前关卡已达到的结论。

- 首关只突出一个新机制，允许跳过示范。
- 中段让玩家比较两种可行顺序。
- 后段组合已学机制，避免靠更多障碍机械堆难度。
- 末关检验本章能力，但不强制三星才能体验后续章节。
- 各章首关继续开放，章内逐关推进。

### 5.3 失败后的选择

失败页首先说明失败原因，再展示“返回棋盘调整”“重新挑战”“请朋友看看”。正常对局一次机会退一步；闯关失败后，一次机会可选择回退 1～3 步，确认成功后统一消耗一次。免费额度与广告补充规则见第 9.2 节。没有证据证明某一步能救局时，不显示“这样一定能通关”。

## 6. 重力试验玩法：落玉庭

### 6.1 为什么值得试

重力连锁可让一次消除产生后续变化，是新鲜感来源。但真正的颗粒流沙涉及新的棋盘表示、交互与胜负规则，不能只看成现有游戏多加一个动画。

先验证格子重力，再决定是否制作完整落沙玩法。惊喜应来自可理解的连锁，而不是无法解释的随机惩罚。

### 6.2 最小原型规则

| 项目 | 首版设计 |
| --- | --- |
| 棋盘 | 默认完整 9×9；6×9 仅作为后续可选变体；首版不混用石障、花圃、钥匙或缺角 |
| 输入 | 沿用三块托盘与拖动落子 |
| 重力触发 | 本次落子产生消除后，进入重力结算；普通未消除的落子不触发 |
| 下落单位 | 单个已占用小格，向正下方落到空位，不保持原拼块形状 |
| 连锁 | 所有格子落稳后统一检查行、列和九宫，再消除、再下落，直到稳定 |
| 补充 | 不从棋盘上方随机补格，仍由托盘供给新方块 |
| 预览 | 提示本次是否会触发下落；完整连锁预览的可读性单独测试 |
| 撤回 | 恢复整次落子前状态，包括连锁、分数与随机序列 |
| 存档 | 保存稳定状态；切后台或被回收后不能丢失半次操作 |
| 成绩 | 独立记录，不进入原庭院地图榜 |

“只有消除才触发下落”必须在入门题明确表达。若玩家普遍认为悬空方块应该立即下落，再测试“每次落子后下落”的替代版本；两种规则分开测，不在同一局中切换。

首批只制作六道体验题和一个自由试验局。暂不加入广告和正式章节奖励。

### 6.3 决定是否扩展

观察玩家能否解释连锁原因、是否主动再玩、是否需要长时间等待结算。至少验证低性能真机、连续撤回、恢复、无可放位置和连锁结束。原型失败可以撤下，不为了已投入成本强行变成第三主模式。

## 7. 邻格解冻：霜封石

现有冰格通过消除所在区域破冰；新的“消除相邻格子解冻”不能使用完全相同的外观与名称。

推荐先在短篇主题题目中试验“霜封石”：

- 不能直接放置方块，外观为覆霜石块，与透明冰格区分。
- 上下左右发生消除时减少一层霜；斜角不算。
- 同一次落子最多减少一层，不因同时消除多个相邻格而重复扣层。
- 霜清完后石块移除，释放可放空间；关卡目标卡使用同一图标。
- 先一层，再两层，之后才与已知机制组合。

它与花圃的邻格触发相似，设计价值必须体现为“打开空间与通路”。如果只是换皮计数，不值得新增。默认方庭不加入该障碍；首版不与重力混合。

## 8. 卡关社交与好友求助

### 8.1 第一阶段：同关求解

复用已有同关邀请。求助卡片包含关卡号、目标、剩余步数和当前棋盘画面，按钮说明“朋友可打开这一关尝试”。朋友实际从原始关卡开始，因此不能宣称为“接手你的残局”。

分享不作为继续游戏的前提，不直接发放复活，不要求转发若干人。退出分享后仍保留原棋盘。

### 8.2 第二阶段：实际残局

分享有效操作记录和规则版本，接收端验证后重建同一状态。朋友的尝试不覆盖原玩家存档，也不混入其主线解锁与正式成绩。

已经无解的局面应支持研究撤回位置，而不是暗示必有下一步。若要自动回传答案或异步发奖，再设计服务端记录、过期处理与校验；第一阶段不为此先建复杂后台。

### 8.3 反馈目标

衡量“求助被打开后是否真正开始尝试”，而不只统计点击分享。不能把调起分享界面当作消息已发出、朋友已收到。

## 9. 体力、广告与奖励

### 9.1 当前不加入基础体力

庭院与主线免费、不限重试。尚未验证留存时，不用次数限制制造回访。未来若试限次，优先限制特别活动的额外奖励领取次数，保留无限练习。

### 9.2 有限撤回与广告补充

默认 9×9、6×9 作为变体，以及有限撤回，是已确认的方向。以下为用户确认的首版规则，已在开发源码实现；真实广告位仍未配置，上线后的调整需根据实际体验与数据决定。

| 场景 | 免费额度 | 后续视频补充 | 使用边界 |
| --- | --- | --- | --- |
| 庭院正常对局 | 每局 1 次机会 | 一次完整视频增加 1 次机会，每局最多成功补充 2 次 | 同一局最多 3 次机会；每次退一步，只能退回已有历史 |
| 闯关挑战 | 每次从开局开始的挑战 1 次机会 | 一次完整视频增加 1 次机会，本次挑战最多成功补充 2 次 | 正常对局一次退一步；失败后一次机会可回退 1～3 步 |
| 每日精选 | 每次从开局开始的挑战 1 次机会 | 首版不接广告补充 | 正常时退一步；失败后同样可一次选择回退 1～3 步；可免费重开 |
| 重力原型 | 每局 1 次机会 | 原型阶段不接广告 | 一次机会恢复整次落子及所有连锁；原型阶段不加失败救场 |

#### 按钮和失败后的回退

- 普通对局显示“撤回 · 剩余 1 次”。额度用完、仍有回退历史且广告可用时，显示“看视频获得 1 次撤回”，由玩家主动点击，不自动播放。
- 闯关失败后，有额度时显示“回退调整 · 剩余 1 次”。打开后选择“退 1 步 / 退 2 步 / 退 3 步”，只显示历史中确实存在的步数。
- 选择步数不立即扣次；确认并恢复成功后统一消耗 1 次。取消、失败或无效操作不扣次。
- 例如：玩家已经用完免费机会，失败后看一次完整视频获得 1 次机会，可以用它直接回退 3 步，不需要连看三次视频。
- 多步回退仅适用于闯关或每日精选的失败状态。回退后恢复正常对局，再次点击普通撤回仍是一次机会退一步，不能继续套用失败时的三步选择。
- 不能保证所选回退步数一定救局，不显示“必过”。没有额度、达到补充上限或广告不可用时，仍保留免费重开和求助。
- 庭院已经判负后，不允许用撤回机会变相复活，包括已领取的视频撤回机会。该状态关闭撤回与撤回补充入口；未来的视频复活是独立功能，每局最多一次，不提供免费复活。

#### 扣次、广告和存档

- 每局免费 1 次机会，视频最多补充 2 次机会，合计最多 3 次机会；“机会数”不等于“累计回退步数”。多步回退不能被拆分成额外机会。
- 首版广告只在额度耗尽时提供补充，不囤积机会。失败/取消观看不发奖励，也不占用成功补充次数；完整观看确认后仅发放一次，重复回调不能重复增加。
- 没有可撤回历史时，不扣次数、不弹视频；动画中不可重复触发操作。看广告前保存本局，发奖后持久化次数；恢复时不重复发奖。
- 剩余机会、已成功补充次数与本局标识独立于棋盘快照保存，撤回不能退还已消耗机会或视频补充次数。
- 返回首页、切后台、重新进入和恢复存档，都延续原有额度。只有真正重开初始棋盘才重置免费额度；重开后不得保留旧棋盘或旧局分数。
- 同一局不会因刷新托盘、获得幸运方块、失败弹窗或关闭弹窗而补满次数。免费与视频机会均不能跨局囤积。
- 引导中的撤回演示如有需要使用独立教学状态，不反复赠送正式对局额度。
- 原庭院只有单步快照；本轮已保存最多 3 步的有限历史并兼容旧存档。闯关多步回退复用操作历史，但要确保一次恢复完整成功后只扣一次机会。
- 对旧存档采用版本迁移：初始化 1 次免费机会并写回，重进不能重复初始化；保留原棋盘与成绩。旧庭院存档仅有一步历史时，只允许回退已有历史，不补造历史。

主线仍可无限次免费重开，这是尝试新解法的基础入口，与无限撤回不同。暂不增加体力或开局次数限制。广告尚未启用时，每局仍只有 1 次免费机会，隐藏视频入口，不以免费补充替代广告奖励。

### 9.3 广告的建议边界

| 功能 | 建议 |
| --- | --- |
| 撤回补充 | 每局免费 1 次机会；一次完整视频补充 1 次，每局最多成功补充 2 次；闯关失败后可用一次机会选择退 1～3 步，详见第 9.2 节 |
| 闯关提示 | 仅在能给出有效帮助时提供，不能看完才发现无建议 |
| 庭院复活 | 每局最多一次；预先说明会如何改变棋盘；不提供免费复活 |
| 外观 | 可考虑短期试用或明确的额外外观进度 |
| 基础游玩 | 不因广告未加载、取消观看而受阻 |

只有完整观看确认后才发放视频奖励；处理重复回调、中途退出和恢复。广告位不可用时隐藏视频入口。复活后的成绩是否进入原榜必须在接入前决定，建议单列辅助成绩或不进入原榜，不能悄悄改变竞争条件。

广告资格、接口和运营规则以实际接入时的微信官方后台与文档核验结果为准；本企划不作资格承诺。

### 9.4 七日来访册

建议累计七个不同日期来访，不要求连续，中断不清零。入口放在“我的庭院”，不强制开局弹窗。

示例奖励：首次来访送淡青外观，第三天送花瓣效果，第七天送小窗景。数值为讨论草案；与现有风铃、小桥等每日完成奖励区分，不重复授予已有物件。

同日只领一次，记录已领取节点。纯本地实现只能满足轻量外观收藏；若未来涉及付费、竞争或高价值奖励，需要可信时间与服务端校验。

## 10. 成长与内容：让玩家看到自己的变化

### 10.1 庭院建设过程

沿用现有收藏统计与目标，增加未完成、中间阶段、完成三个视觉状态。例如嫩芽变成修竹、石灯逐渐点亮。中间状态只是展示，不另造资源经济。

已获得装饰可以自由显示或隐藏。结算展示物件变化，首页能找到同一个物件和获得原因。

### 10.2 每周主题

在现有每日精选中按主题组织题目，先核对题目是否真的符合主题，不只更换标题。内容节奏可为“单机制学习、熟练应用、周末组合题”。固定日期与题目版本关系，避免更新后同一天好友面对不同题。

已落地七题试行库：空间规划、行列接力、花圃、同步消除与机关组合；新版三星参考路线为 9～10 步，通关多留 3 步。旧题编号、晚更新的旧局和旧成绩保留；同日新旧题目分开记最佳步数。实现和验证记录见 `../daily-week-one/新版每日挑战说明.txt`，仍需真人试玩校准难度。

### 10.3 后续候选：短篇残局集

在主线之外提供少量“一到三步完成目标”的残局，帮助玩家练观察和理解消除顺序。先用经过验证的作者题目，不把随机生成的死局当挑战。只有主线目标已能被新玩家理解后再做，避免入口继续膨胀。

## 11. 交互、视觉与音效

| 环节 | 建议改进 | 验收重点 |
| --- | --- | --- |
| 首页 | 玩法说明＋当前成长目标＋明确主按钮 | 不靠阅读设置理解游戏；不堆签到、活动等入口 |
| 目标卡 | 图标与棋盘一致，主目标最大，步数紧邻 | 新玩家能说出本关结束条件 |
| 目标说明 | 点击目标可重看短说明和示例；不直接给完整解法 | 学过但忘记的人无需翻设置 |
| 拖动 | 保留抬升、清楚的合法落点、会消除区域高亮 | 手指不遮挡关键落点，不只依赖颜色 |
| 无效操作 | 一句原因，不扣步；不要每次都强震动 | 玩家知道下一步能尝试什么 |
| 消除 | 普通消除轻快，多重消除更突出 | 动画不拖慢连续操作 |
| 机制结果 | 先看到破冰、浇花、开门，再看到进度更新 | 数字变化可被解释 |
| 奖励 | 从结算指向对应收藏位置 | 玩家知道奖励在哪里 |
| 失败 | 具体原因＋调整、重试、求助 | 不伪造“只差一点” |
| 可访问性 | 简化动效、音效/音乐/震动独立设置 | 小屏、静音和色觉差异下仍能理解 |

保留庭院米白青绿、闯关清晰冷色的现有分工，统一按钮、图标与动作节奏。落玉庭用温润玉粒表达重力，避免突然换成高饱和霓虹风。

背景音乐维持现状。连锁音效使用现有音色变化，限制同时播放数量与总响度；重点事件轻触觉反馈即可。动效参数先作为原型变量，不在未试玩前固定为最终标准。

## 14. 如何验证改版是否有效

### 14.1 先做目标理解测试

邀请约 8—12 名未玩过的用户，分两轮，每轮约 4—6 人。不开口教操作，先观察，再询问：

1. 你觉得这个模式要完成什么？
2. 什么操作会让你更接近目标？
3. 什么时候算这一局结束？
4. 这局结束后，你得到了什么？
5. 你还想再玩一局吗，为什么？

第一轮发现问题后改表达，第二轮用新参与者验证。可暂定“至少 80% 能在体验后正确复述本局目标”为内部方向性门槛；小样本不能证明留存或商业收益。

### 14.2 数据口径

| 指标 | 建议定义 |
| --- | --- |
| 首消完成率 | 完成首次消除的新玩家 / 进入首次可操作棋盘的新玩家 |
| 第二局启动率 | 首局结束后同次访问又开始一局的新玩家 / 首局结束的新玩家 |
| 失败后重试率 | 失败后进行重开或撤回继续尝试的次数 / 失败次数；两种行为分别记录 |
| 求助转化 | 从求助入口打开且开始尝试的访问 / 可识别的求助打开访问 |
| 收藏理解 | 真人能指出当前目标和剩余条件的比例；点击收藏不能代替理解 |
| 次日留存 | 某日首次进入的用户中，次日再次进入的比例；按本地业务日期统一口径 |
| 广告奖励成功率 | 收到完整观看确认后成功且仅成功发奖一次的次数 / 完整观看确认次数 |

先核对已有事件的后台配置和数据接收；尽量复用，不重复建设统计系统。首局、老玩家、不同地图分别观察。没有真实基线时不承诺提升百分比；小流量先做连续观察，不强行解释成显著 A/B 结果。

- 企划已有部分落地，具体范围以对应更新记录为准；开发改动不等于已更新发布副本或线上版本。

- 重力结算不依赖屏幕帧率决定结果；随机序列可重放，撤回不能重新抽奖。
- 校验触摸取消、多指、后台恢复、动画中断、广告取消、重复奖励与失败存档。
- 撤回专项验收：每局免费 1 次机会、每个完整视频补充 1 次、每局最多成功补充 2 次；正常每次退一步，闯关失败后选退 1～3 步只扣一次；取消选择不扣次；回退后恢复单步规则；扣次不随棋盘回退；重启不补次；无历史不扣次；重开完全重置棋盘；庭院判负后所有撤回机会都不能续命；旧存档只迁移一次。
- 开源效果先独立试验，验证帧耗时、内存、包体和素材许可后再考虑纳入。
- 开发版验证完成后重新生成并加固发布副本，不覆盖已有稳定发布快照。
- 若重力玩法普遍难以理解、性能不达标或没有主动重玩意愿，暂停扩展；若签到只带来领奖不带来游玩，减少奖励入口而不是继续加任务。
